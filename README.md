# Mini-Redis: In-Memory Key-Value Store in Erlang

A lightweight, concurrent in-memory Key-Value store with TTL auto-expiration built using Erlang.

---

## What Does This Project Do?

In modern web applications (like Netflix, Instagram, or Twitter), constantly querying a disk-based database (PostgreSQL, MySQL) for small, frequent checks like user sessions, login tokens, or rate limits creates massive bottlenecks.

Tools like **Redis** solve this by storing data directly in **RAM** for sub-millisecond lookups. 

This project implements that exact system natively inside Erlang without requiring any external servers:
* **High-Speed RAM Storage:** Store and read data in fractions of a millisecond.
* **Auto-Expiring Keys (TTL):** Store one-time passwords (OTP) or temporary tokens that automatically self-destruct after $X$ milliseconds.
* **No Locks or Mutexes:** Uses isolated Erlang processes (actors) communicating purely through message passing.

## Project Architecture & Files

| File | Type | Purpose |
| :--- | :--- | :--- |
| **[`cli.erl`](cli.erl)** | Source (`.erl`) | Interactive command-line interface (REPL) like `redis-cli`. |
| **[`mini_kv.erl`](mini_kv.erl)** | Source (`.erl`) | Raw Actor Model implementation (`spawn`, `!`, `receive`, tail-recursion). |
| **[`mini_kv_otp.erl`](mini_kv_otp.erl)** | Source (`.erl`) | Production standard Erlang/OTP implementation (`gen_server`). |
| **[`demo.erl`](demo.erl)** | Source (`.erl`) | Automated test suite that validates both implementations. |
| **`*.beam`** | Bytecode | Compiled binary files generated by `erlc` executed by the BEAM VM. |

> **Note on `.erl` vs `.beam`:** 
> `.erl` is the human-readable code you write. When compiled with `erlc`, Erlang generates `.beam` bytecode files that the computer executes. `.beam` files can be safely deleted and recompiled at any time.

## How to Run

### 1. Interactive CLI Mode (Recommended)

Compile the code and start the interactive CLI:

```powershell
erlc cli.erl mini_kv.erl
erl -noshell -s cli start
```

Once the `mini-redis>` prompt appears, type your commands:

```text
mini-redis> SET name Lawrence
OK: Stored name => "Lawrence"

mini-redis> GET name
VALUE: "Lawrence"

mini-redis> SETEX otp 948201 5000
OK: Stored otp => "948201" (Expires in 5000 ms)

mini-redis> GET otp
VALUE: "948201"

mini-redis> KEYS
Active Keys (2):
  * name
  * otp

(wait 5 seconds for OTP to self-destruct...)

mini-redis> GET otp
(nil) - Key does not exist or has expired.

mini-redis> STATS
--- Store Statistics ---
  Active Items  : 1
  Total Reads   : 3
  Total Writes  : 2
  Total Deletes : 0

mini-redis> QUIT
Exiting Mini-Redis. Goodbye!
```

---

### 2. Available CLI Commands

| Command | Syntax | Description | Example |
| :--- | :--- | :--- | :--- |
| **SET** | `SET <key> <value>` | Stores a key and value indefinitely | `SET username admin` |
| **SETEX** | `SETEX <key> <value> <ms>` | Stores with TTL (milliseconds) | `SETEX token abc123 60000` |
| **GET** | `GET <key>` | Retrieves the value for a key | `GET username` |
| **DEL** | `DEL <key>` | Deletes a key from storage | `DEL username` |
| **KEYS** | `KEYS` | Lists all active keys | `KEYS` |
| **SIZE** | `SIZE` | Counts stored items | `SIZE` |
| **STATS** | `STATS` | Displays reads, writes, deletes | `STATS` |
| **CLEAR** | `CLEAR` | Wipes the entire database | `CLEAR` |
| **HELP** | `HELP` | Shows the command menu | `HELP` |
| **QUIT** | `QUIT` / `EXIT` | Exits the program | `QUIT` |

## Core Erlang Concepts Learned

### 1. State Without Mutation (Tail-Recursion)
Variables in Erlang are strictly immutable. To maintain state, an Erlang process calls itself in an infinite tail-recursive loop, passing the updated state dictionary into the next iteration:

```erlang
loop(State) ->
    receive
        {put, Key, Value} ->
            NewState = maps:put(Key, Value, State),
            loop(NewState)   %% State persists into the next cycle!
    end.
```

### 2. Synchronous (`call`) vs. Asynchronous (`cast`)
* **Synchronous (`call`):** The caller includes its process ID (`self()`) and waits on `{reply, Reply}` (used for `GET`, `STATS`, `KEYS`).
* **Asynchronous (`cast`):** Fire-and-forget. The caller sends the message and continues immediately without waiting (used for `PUT`, `DELETE`, `CLEAR`).

### 3. Native Lightweight Timers
Instead of running a background cleanup thread or periodic cron job, Erlang allows processes to schedule timer messages with zero overhead:

```erlang
TimerRef = erlang:send_after(Ms, self(), {expire, Key})
```
When `Ms` milliseconds pass, the BEAM VM automatically sends `{expire, Key}` to the process mailbox, which removes the key from the map.
